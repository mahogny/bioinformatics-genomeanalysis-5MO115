Exploring the command line

🎯 Objective

Practice fundamental command-line skills by navigating through directories, creating new folders, and manipulating files.

📝 Instructions

Open your terminal

Depending on the operating system you are using you will find the terminal in different locations.

HPC2N
Follow instructions on separate page; You can use OnDemand or access via SSH

Ubuntu in Windows
1. First, follow the installation instructions for WSL2
2. You can directly start Ubuntu by searching for “Ubuntu” in the Start menu and select the installed Ubuntu distribution

macOS
Click the Launchpad symbol in Dock, write Terminal in seach bar
or
Open folder /Apps/Tools in Finder and click on Terminal

Create folder for exercise

Start with figuring out what folder you are currently located in using the pwd command

See code: 
pwd

Navigate to the position where you want to create your new working directory. Use cd to move between folders. To go one step up in the tree structure you use cd .., and to go into a specific folder you use cd <name of folder>. Use pwd frequently to orient yourself where in the folder structure you currently are.

See example code: 
# Go two step up, and then one step down into another folder (this precise command will not work on HPC2N, but try other commands!):
cd ../../Documents/

Create a folder called exercises_module2.

See code: 
mkdir exercises_module2

Set up folder structure for project

cd into this folder and create the following subfolders:

  • rawdata
  • tempfolder
  • processed_data
See code: 
cd exercises_module2
mkdir rawdata
mkdir tempfolder
mkdir processed_data

Use pwd and ls to make sure that you are in the correct place and the folders have been created correctly. If the folders where created somewhere you did not want them to be, you can remove empty folders with rmdir. Always make it a habit to use pwd and ls often, to verify that you are in the correct folder.

Add some documentation

It is good practice to always add documentation to any bioinformatics project you start, for documenting the purpose of the project, and any meta data.

Create a file called README.txt where you put the following text:

This folder is part of the linux and R exercises for module 2. It consists of the following folders:

- rawdata: contains downloaded raw data
- tempfolder: contains all intermediary files not to be kept
- processed_data: contains the processed data to be saved


See code: 
touch README.txt
nano README.txt
# write the text above, save with Ctrl+O, close with Ctrl+X

Subset the data

Now let’s split up the data we have in Male and Female, and create 2 separate files, called health_data_test_male.tsv and health_data_test_female.tsv. Use grep, >, and >> to create 2 new files, that should be placed in the folder processed_data. Remember to also include the header line in both files. To solve this, first make sure to inspect the file and find out how you can grep to get the results you want.

See code: 
cd ..  # make sure you are in the exercises_module2 folder 
grep ID rawdata/health_data_test.tsv > processed_data/health_data_test_male.tsv 
grep Male rawdata/health_data_test.tsv >> processed_data/health_data_test_male.tsv 

grep ID rawdata/health_data_test.tsv > processed_data/health_data_test_female.tsv 
grep Female rawdata/health_data_test.tsv >> processed_data/health_data_test_female.tsv

The solution above is dependent on you being in the exercise_module2/ folder. If you instead are in the rawdata/ folder, the solution would look like this, with the relative paths:

See code: 
cd ..  # make sure you are in the exercises_module2 folder 
grep ID health_data_test.tsv > ../processed_data/health_data_test_male.tsv 
grep Male health_data_test.tsv >> ../processed_data/health_data_test_male.tsv 

grep ID health_data_test.tsv > ../processed_data/health_data_test_female.tsv 
grep Female health_data_test.tsv >> ../processed_data/health_data_test_female.tsv

Make sure to inspect the files and verify that everything looks like it should.

Now you have the basic commands needed to navigate the command line and do some basic file manipulations

Extra exercise material

A second pass at the same material, for extra practice. These exercises assume you still have the exercises_module2 folder with rawdata/health_data_test.tsv from the main exercise. If not, recreate it first.

Navigation (extra)

  • QE1.1 From wherever you currently are, jump straight to your home directory with a single short command, then jump back to the previous directory you were in. Which two shortcuts let you do this without typing out the full paths?
Hint

The tilde character ~ is a shortcut for your home folder. The dash - is a shortcut for the previous directory.

Solution 
cd ~      # go to home directory
cd -      # go back to the previous directory
  • QE1.2 Starting from inside exercises_module2/rawdata, navigate into processed_data using a relative path (with ..). Then do the same thing again using an absolute path (starting with /). Use pwd after each step to verify where you are.
Hint

Relative paths use .. to go one level up. Absolute paths always start with / and spell out the location from the root of the filesystem. pwd prints the absolute path of your current folder, which you can copy.

Solution 
# relative path
cd ../processed_data
pwd

# back, then with absolute path (replace with the output of pwd)
cd -
cd /home/yourusername/exercises_module2/processed_data
pwd

Listing files (extra)

  • QE2.1 List the contents of the exercises_module2 folder showing all files (including hidden ones), in long format, with human-readable file sizes. Then sort the listing by file size, and again by modification time.
Hint

Combine ls flags: -l (long), -a (all, including hidden files starting with .), -h (human-readable sizes). Use -S to sort by size, -t to sort by time.

Solution 
cd ~/exercises_module2
ls -lah
ls -lahS    # sorted by size (largest first)
ls -laht    # sorted by modification time (newest first)
  • QE2.2 Inside the processed_data folder, list only the files matching the pattern health_data_test_*.tsv. Then list only files whose name starts with health_data_test_ followed by exactly one letter from {m, f}, ending in .tsv.
Hint

* matches any sequence of characters. [abc] matches a single character from the set a, b, or c. ? matches exactly one of any character.

Solution 
cd ~/exercises_module2/processed_data
ls health_data_test_*.tsv
ls health_data_test_[mf]*.tsv

File inspection (extra)

  • QE3.1 Show only the first 5 lines of rawdata/health_data_test.tsv, then only the last 20 lines. Finally, count how many lines the file has in total.
Hint

head -n N file shows the first N lines. tail -n N file shows the last N lines. wc -l file counts the lines.

Solution 
cd ~/exercises_module2
head -n 5 rawdata/health_data_test.tsv
tail -n 20 rawdata/health_data_test.tsv
wc -l rawdata/health_data_test.tsv
  • QE3.2 Open rawdata/health_data_test.tsv in less and practice the following keyboard shortcuts: jump to the end of the file, jump back to the beginning, search forward for the word Female, then quit less.
Hint

In less: press G to jump to the end, lowercase g to jump to the beginning, /pattern (then Enter) to search forward, n to jump to the next match, and q to quit.

Solution 
less rawdata/health_data_test.tsv
# inside less:
#   G        -> end of file
#   g        -> start of file
#   /Female  -> search forward for "Female", then press Enter
#   n        -> jump to next match
#   q        -> quit less

History and recall (extra)

  • QE4.1 You just ran a long grep command and want to re-run it without retyping. Use !! to repeat your very last command. Then run a new command (wc -l) that operates on the same file that was the last argument to the previous command — use the !$ shortcut for that.
Hint

!! expands to the entire previous command. !$ expands to the last argument of the previous command. They are pure text expansions, so the shell will show you what gets executed.

Solution 
grep Female rawdata/health_data_test.tsv
!!                     # re-runs: grep Female rawdata/health_data_test.tsv
wc -l !$               # expands to: wc -l rawdata/health_data_test.tsv
  • QE4.2 Find a grep command you ran earlier in the session in two different ways: first by using Ctrl-R to do a reverse-incremental search through your history, then by piping history through grep.
Hint

Ctrl-R opens an interactive reverse search; start typing part of the command and press Enter to run the match (or arrow keys/Esc to edit it). history prints your numbered command history, which you can pipe to grep.

Solution 
# Option 1: press Ctrl-R, then type "grep" -- bash shows the most recent match.
#           Press Ctrl-R again to step further back, Enter to run, Esc to edit.

# Option 2:
history | grep grep

A bioinformatics flavour (extra)

  • QE5.1 FASTQ files store sequencing reads, with 4 lines per read (a header starting with @, the sequence, a + separator, and the quality string). Suppose you have a file reads.fastq in your rawdata folder. Write a command that counts how many lines it has, and then explain how you would get the number of reads from that. (You can test this on health_data_test.tsv if you don’t have a real FASTQ file at hand — the line-counting command is the same.)
Hint

wc -l file gives you the number of lines. To get the number of reads in a FASTQ file, divide the line count by 4.

Hint 2

You can do the arithmetic directly in bash with $(( ... )), combined with command substitution $(...):

echo $(( $(wc -l < file) / 4 ))
Solution 
# Count lines
wc -l rawdata/reads.fastq

# Number of reads = lines / 4. One-liner:
echo $(( $(wc -l < rawdata/reads.fastq) / 4 ))

# For a gzipped FASTQ (reads.fastq.gz), stream it through zcat first:
echo $(( $(zcat rawdata/reads.fastq.gz | wc -l) / 4 ))
