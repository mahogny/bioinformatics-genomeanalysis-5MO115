4.4 RNA-seq analysis

In this module we will finally perform an RNA-seq analysis, putting previous modules into action!

From FASTQ to count matrix

Learn first how to align raw sequencing data, and produce a count matrix: The count matrix represents RNA molecule counts, and is obtained after aligning sequencing data, and comparing with the reference gene annotation. We will explain how to get this count matrix the common way, but also an incredibly fast shortcut to it using linear algebra (Canvas/Kaltura video: 4_5_alignment_for_rnaseq v2).

  • As mentioned, salmon is a pseudocount tool, going from FASTQ to count matrix directly. You can read more here: https://combine-lab.github.io/salmon/about
  • Salmon guide

Get Salmon for pseudocounting:

  • if you use HPC2N, you can load it through:

    ml load GCC/13.2.0 Salmon/1.10.3

  • If you run on your own computer, you can install it through conda.

Check that it runs by simply typing salmon in the terminal. You should get a help page.

Quantify the number RNA molecules per gene:

Using the index you downloaded, stored in directory salmon_human_index, you can estimate the number of RNA molecules for each gene using this command:

salmon quant -i salmon_human_index -l A \
    -r RUN466-20-26210-CLBGA-IC50-Celasterol-RNAseq5BR_S12_L001_R1_001.fastq.gz \
    -p 1 --validateMappings -o quants/IC50_5_quant

Here -p 1 means to use one CPU. You can arrange to use multiple if you want. The output is specified using -o.

Note

You can put \ at the end of any bash command lines if you want to manually divide them up to increase readability. But be careful when copying above as there cannot be any newlines when you paste it in (bash will then think that you are giving it 3 separate commands, and fail).

Load the counts in R:

As is common, data is not always stored in the simplest format. We have written some code here to enable you to read the counts for each library into one matrix in R. It assumes that you stored all outputs in the directory ~/glio/quants/.

## Read each separate salmon output of counts
all_counts <- list()
rootdir <- "~/glio/quants/"
for (f in list.files(rootdir)) {
  print(f)
  onedat <- read.csv(file.path(rootdir, f, "quant.sf"), sep = "\t")[, c("Name", "NumReads")]
  onedat$f <- f
  all_counts[[f]] <- onedat
}
## Put into one single count matrix
cnt <- reshape2::acast(do.call(rbind, all_counts), Name ~ f, value.var = "NumReads")

Differential expression analysis

See this video, showing the overall workflow from counts to statistical test (Canvas/Kaltura: 4.3 deseq).

  • Model matrices are central to analysis of RNA-seq, microarray, proteomic and what-have-you data. Once you grasp this concept, you can do most bioinformatics statistical analysis!

  • You will see that you can model a simple comparison between condition A and B (for two samples) as

    \[ \begin{bmatrix} \text{counts}_A \\ \text{counts}_B \end{bmatrix} \sim \mathrm{Poisson}\!\left( \begin{bmatrix} 1 & 0 \\ 1 & 1 \end{bmatrix} \begin{bmatrix} \text{baseline} \\ \text{treatment} \end{bmatrix} \right) \]

    and then just compute \(P(\text{baseline}_2 < q)\).

    • The model matrix is \(\begin{bmatrix} 1 & 0 \\ 1 & 1 \end{bmatrix}\).
    • \(P(\text{treatment} < q)\) is being evaluated to see if the expression is different from 0.
    • We call \(\text{treatment}\) a contrast.

  • Alternatively, equivalently,

    \[ \begin{bmatrix} \text{counts}_A \\ \text{counts}_B \end{bmatrix} \sim \mathrm{Poisson}\!\left( \begin{bmatrix} 1 & 0 \\ 0 & 1 \end{bmatrix} \begin{bmatrix} \text{baseline}_1 \\ \text{baseline}_2 \end{bmatrix} \right) \]

    but the test becomes a bit more complicated instead: \(P(\text{baseline}_2 - \text{baseline}_1 < q)\).

    • The model matrix is \(\begin{bmatrix} 1 & 0 \\ 0 & 1 \end{bmatrix}\).
    • \(P(\text{baseline}_2 - \text{baseline}_1 < q)\) is evaluated to see if it is different from 0.
    • \(\text{baseline}_2 - \text{baseline}_1\) is the contrast in this case.

  • The Poisson distribution we looked at only models the sequencing process. To also account for biological variation, we will instead use the negative binomial distribution, which turns out to be a natural extension. Optional reading at Wikipedia.

  • Optional reading on the origin of the negative binomial distribution, but even better is the DESeq2 paper.

Differential expression theory:

  • Q2.1: Using pen and paper, convince yourself that log(fold change) = 0 means that there is no change.
Hint

What value of \(x\) gives \(\log(x) = 0\)? And what does that value of the fold change \(x = \text{new}/\text{old}\) mean?

Solution

\(\log(x) = 0 \iff x = 1\). A fold change of \(1 = \text{new}/\text{old}\) means \(\text{new} = \text{old}\), i.e. no change in expression.

  • Q2.2: Using pen and paper, convince yourself that high −log(p-value) means smaller p-values, and thus higher significance.
Hint

\(\log\) is monotonically increasing, so as \(p\) decreases, \(\log(p)\) decreases, and \(-\log(p)\) increases.

Solution

For \(p \in (0, 1]\), \(\log(p) \le 0\), so \(-\log(p) \ge 0\). As \(p \to 0\), \(-\log(p) \to \infty\). Thus a high \(-\log_{10}(p)\) on the y-axis corresponds to a tiny p-value, i.e. a more significant result.

Set up the condition data frame:

To run DESeq2 or any similar package, you need a data frame with information about the samples. The row names should correspond to sample names (i.e. column names in the count matrix). If you don’t have a condition data frame, you can often create it from the names of the samples. This is a starting point:

cond <- data.frame(
  row.names = colnames(cnt)
)
cond$treatment <- ...

You want to obtain a column called treatment, for each sample. In this case, DMSO and IC50 (or anything you prefer that is human-interpretable).

Run DESeq2 to fit statistical model:

You are now ready to perform the statistical analysis! The following code, largely taken from the vignette (recommended reading!), sets up a pairwise test.

dds <- DESeqDataSetFromMatrix(
  countData = round(cnt),  # salmon output non-integer counts; round to integer to fix
  colData   = cond,
  design    = ~ treatment  # specifies model matrix
)
dds <- DESeq(dds)
res <- results(dds, c("treatment", "a", "b"))  # set appropriately
  • Q2.4: Adjust to compare treated and untreated samples.
Hint

The contrast argument to results() is c(factor_name, level_numerator, level_denominator). Here the factor is treatment, the levels are IC50 (treated) and DMSO (control).

Solution 
dds <- DESeqDataSetFromMatrix(
  countData = round(cnt),
  colData   = cond,
  design    = ~ treatment
)
dds <- DESeq(dds)
res <- results(dds, c("treatment", "IC50", "DMSO"))
  • Q2.5: What does the model matrix look like? Does it make sense as compared to the video explanation? (hint: typical exam material!)
Hint

Try model.matrix(~ treatment, data = cond) in R and inspect the rows and columns.

Hint

Compare what you see against the two model-matrix formulations in the video / above (the \(\begin{bmatrix} 1 & 0 \\ 1 & 1 \end{bmatrix}\) vs. \(\begin{bmatrix} 1 & 0 \\ 0 & 1 \end{bmatrix}\) examples). Which one is R using? What does each column represent (intercept vs. treatment effect)?

Solution 
model.matrix(~ treatment, data = cond)

With two treatment levels (DMSO and IC50) and the default treatment-coding, R picks the first level (alphabetically: DMSO) as the reference. You get a column of 1s (the intercept = DMSO baseline) plus one column that is 1 for IC50 samples and 0 for DMSO samples. This is the first formulation from the video, \[ \begin{bmatrix} 1 & 0 \\ 1 & 0 \\ 1 & 1 \\ 1 & 1 \end{bmatrix}, \] where the second column directly encodes the treatment effect (the contrast). The second formulation in the video uses two intercepts (one per group) and you compute the contrast as the difference of the two — equivalent, just parameterised differently.

Extract the differentially expressed genes and make a volcano plot:

The output list of genes (unsorted) will look kind of like below.

  • log2FoldChange is the log2(fold change) and what most are interested in.

  • padj is multiple-hypothesis-testing-adjusted p-value.

  • Q2.6: Adjusted p-value — this means adjusted for multiple hypothesis testing. What does this mean? This video explains: https://www.youtube.com/watch?v=HLzS5wPqWR0

Hint

If you test 20,000 genes at \(p < 0.05\), how many false positives would you expect by chance alone?

Solution

Testing tens of thousands of genes simultaneously means many will appear significant by chance alone (at \(p < 0.05\), about 5% of all tests). The adjusted p-value (DESeq2 uses Benjamini–Hochberg by default) controls the false discovery rate (FDR) — the expected proportion of false positives among the genes called significant. Use padj rather than raw pvalue when picking hits.

  • Q2.7: Make a volcano plot to aid interpretation. This plot is designed as follows:
    • x-axis: log2 fold change
    • y-axis: −log10 adjusted p-value
Hint

This is just using ggplot, nothing new! Convert the DESeq2 result to a data frame and use geom_point.

Solution

Perform DE analysis using DESeq2

There is much more you can compare here, since you got both (1) cell type and (2) time since treatment. We will return to this dataset in Module 5 to perform unsupervised machine learning.

Note that there is metadata that you can ignore, such as the position of the sample on the multiwell plate where the sample was prepared.

You can build a multilinear equation describing the expression of genes as: ~ cell_type + treatment_duration + time_since_treatment.

  • Q3.4 Does this model make sense? No model is perfect! Are there any assumptions built into the model? (this question has no single correct answer)
Hint

The formula ~ cell_type + treatment_duration + time_since_treatment has no : or * terms. What does that mean about how the three factors are assumed to interact?

Solution

The + form assumes purely additive effects on \(\log\) expression — each factor shifts expression independently of the others. In reality, the response to a drug may very well depend on the cell line (a cell-type × treatment interaction), which this model cannot capture. To allow that, you would add an interaction term such as ~ cell_type * treatment_duration. The model also assumes the replicates are independent samples, that the negative-binomial mean-variance relationship holds, and that no important confounders (e.g. batch / plate position) are missing.

  • Q3.5 What does the model matrix look like? Note as above that there are multiple model matrices that could be used for this problem. How would you have preferred to construct it?
Hint

Use model.matrix(~ cell_type + treatment_duration + time_since_treatment, data = cond) and inspect the columns: there is an intercept column, then one indicator column per non-reference level of each factor.

Solution 
mm <- model.matrix(~ cell_type + treatment_duration + time_since_treatment, data = cond)
head(mm)

The first column is the intercept (the reference cell line / no treatment / earliest time). Each remaining column is an indicator for one non-reference level. With \(k\) levels in a factor you get \(k-1\) columns (treatment contrasts). An alternative is the “no-intercept” parametrisation ~ 0 + cell_type + treatment_duration + time_since_treatment, which gives one column per level — easier to read for some contrasts but you still need to choose contrasts carefully.

Lineage-marker genes (e.g. tissue-specific transcription factors of the cell types you identified in Q3.1) often top the list.

Alignment and quantification (extra)

  • QE1.1 What does the --validateMappings flag do in salmon quant, and why would you usually want it on?
Hint

Pseudoalignment by itself only checks which transcripts a read’s k-mers are compatible with. --validateMappings adds an extra step on top of that.

Solution

--validateMappings enables selective alignment: after the fast k-mer-based mapping step, salmon does a lightweight scoring of each candidate mapping against the transcript sequence (similar in spirit to a Smith–Waterman score). This filters out spurious mappings that happen to share k-mers but do not actually align well, giving more accurate quantification at a small extra CPU cost. It is on by default in newer salmon versions and is the recommended setting.

  • QE1.2 Why use a pseudoaligner like salmon instead of a full splice-aware aligner like STAR or BWA when all you want is a gene-level count matrix?
Hint

Think about what information you actually use downstream (just NumReads per transcript), and what STAR/BWA spend most of their time computing.

Solution

Full aligners produce a base-resolution BAM with the exact genomic coordinate of every read — useful for variant calling, splice-junction discovery, coverage tracks, etc. For a count matrix you only need to know which transcript a read came from, not where on it. Pseudoalignment skips the per-base alignment and is typically 10–100× faster with comparable quantification accuracy. Trade-off: you cannot reuse the output for SNP calling or coverage plots.

  • QE1.3 Open one of the quant.sf files salmon produced. What are the columns, and which one did we actually use when we built cnt?
Hint

head quants/IC50_1_quant/quant.sf in bash, or read.csv(..., sep = "\t") in R.

Solution 
head(read.csv("quants/IC50_1_quant/quant.sf", sep = "\t"))

Columns are Name (transcript ID), Length, EffectiveLength (length corrected for fragment-size distribution), TPM (transcripts per million — length-normalised), and NumReads (estimated read count, possibly fractional from EM). We used NumReads because DESeq2 wants raw counts, not TPM. TPM is for visualisation / within-sample comparison, not for DE testing.

DESeq2 differential expression (extra)

  • QE2.1 DESeq2 internally normalises libraries with size factors rather than scaling to TPM. Inspect them and explain what they correct for.
Hint

sizeFactors(dds) after DESeq(dds). Compare them to colSums(counts(dds)).

Solution 
sizeFactors(dds)
colSums(counts(dds))

Size factors correct for differences in sequencing depth between libraries, and (because they use the median-of-ratios method, not total counts) they are robust to a handful of very highly expressed genes dominating one library. Each raw count is internally divided by its sample’s size factor before fitting.

  • QE2.2 Inspect the per-gene dispersion estimates with plotDispEsts(dds). What should the plot look like if the model is behaving well?
Hint

There are three things on the plot: per-gene estimates (black), a fitted trend (red), and shrunken final values (blue).

Solution 
plotDispEsts(dds)

You want to see dispersion decreasing with mean expression (highly expressed genes are more reproducible), the red trend line passing through the cloud of black dots, and the blue shrunken estimates pulled toward the red curve — strongest shrinkage for low-count genes where the per-gene estimate is unreliable. Bad signs: trend line clearly off the cloud, or dispersions not decreasing with the mean (suggests outliers or a missing covariate).

  • QE2.3 Make an MA plot with plotMA(res) and explain the axes. What does a “good” MA plot look like for a treatment-vs-control comparison?
Hint

M and A come from microarray days: M = log-ratio, A = average log-intensity.

Solution 
plotMA(res, ylim = c(-5, 5))

x-axis (A) is the mean of normalised counts across all samples (log scale). y-axis (M) is the log2FoldChange. Significant genes (padj < 0.05) are coloured. Expectations: the cloud should be centred on M = 0 (most genes do not change), it should funnel — wider at low mean expression where estimates are noisier, narrower at high mean — and significant points should be the ones farthest from y = 0. A cloud that is shifted off zero suggests a normalisation problem.

  • QE2.4 Run summary(res) and interpret the output. How many genes go up, how many go down, at the default thresholds?
Hint

summary prints LFC > 0 (up), LFC < 0 (down), outliers, and low-count genes filtered by independent filtering.

Solution 
summary(res)

The output lists: total genes tested, the default alpha (FDR threshold, 0.1 unless you set otherwise), number of genes with LFC > 0 (up in numerator vs. denominator) and LFC < 0 (down), how many were flagged as outliers (Cook’s distance) and how many were filtered out by independent filtering of low-count genes (which increases statistical power on the genes that remain). You can tighten this with summary(res, alpha = 0.05).

  • QE2.5 Pick a stricter cutoff than just padj: keep genes with padj < 0.05 and abs(log2FoldChange) > 1. How many are left?
Hint

log2FoldChange > 1 means at least a 2-fold change. Watch out for NA values in padj from independent filtering.

Solution 
res_df <- as.data.frame(res)
sig <- subset(res_df, !is.na(padj) & padj < 0.05 & abs(log2FoldChange) > 1)
nrow(sig)
head(sig[order(sig$padj), ])

abs(log2FoldChange) > 1 corresponds to at least a 2-fold up- or down-regulation. Combining it with padj removes genes that are statistically significant but biologically tiny (common with very deep sequencing — tiny shifts get tiny p-values).

Model matrices and contrasts (extra)

  • QE2.6 Suppose you want IC50 to be the reference level instead of the default alphabetical pick (DMSO). Use relevel to do this and re-fit. Does the model matrix or the contrast change?
Hint

cond$treatment <- relevel(factor(cond$treatment), ref = "IC50") before constructing dds.

Solution 
cond$treatment <- relevel(factor(cond$treatment), ref = "IC50")
dds <- DESeqDataSetFromMatrix(round(cnt), cond, ~ treatment)
dds <- DESeq(dds)
resultsNames(dds)  # now "treatment_DMSO_vs_IC50"

The model matrix still has two columns (intercept + one indicator), but the indicator column is now 1 for DMSO samples instead of for IC50 samples. The fitted log-fold change has the opposite sign of before — same biology, different reference. Always check resultsNames(dds) (or the contrast = argument to results()) to know which direction you are looking at.

  • QE2.7 What does model.matrix(~ 0 + treatment, data = cond) look like (the no-intercept form), and how would you extract the IC50-vs-DMSO contrast from a dds fitted with design = ~ 0 + treatment?
Hint

With ~ 0 + treatment there is no intercept column; instead you get one column per level, each acting as a per-group mean.

Solution 
model.matrix(~ 0 + treatment, data = cond)

You get a matrix with two columns, treatmentDMSO and treatmentIC50, each with 1s for samples in that group and 0s otherwise (it is the second formulation from the lecture — \(\begin{bmatrix} 1 & 0 \\ 0 & 1 \end{bmatrix}\)). There is no overall intercept; each column directly estimates the log expression of that group. To get the IC50-vs-DMSO contrast you have to subtract the two coefficients explicitly:

dds <- DESeqDataSetFromMatrix(round(cnt), cond, ~ 0 + treatment)
dds <- DESeq(dds)
res <- results(dds, contrast = c("treatment", "IC50", "DMSO"))
# or equivalently with a numeric contrast vector:
res <- results(dds, contrast = c(-1, 1))   # matches order of resultsNames

Same answer as the with-intercept version — just a different parametrisation.

  • QE2.8 A reviewer asks: “your design has 4 samples and 1 factor with 2 levels — how many parameters does your model actually estimate per gene?” Answer using the model matrix.
Hint

Number of parameters = number of columns of the model matrix. Residual degrees of freedom = \(n_\text{samples} - n_\text{params}\).

Solution

With ~ treatment and two levels, the model matrix has 2 columns (intercept + treatment indicator), so 2 parameters per gene. With 4 samples that leaves 2 residual degrees of freedom — exactly enough to estimate within-group variance from the 2 replicates per group. If you had only 1 replicate per group you would have 0 residual d.f. and DESeq2 would refuse to estimate dispersion.

Multivariate designs (extra)

  • QE3.1 Re-fit the E-MTAB-14822 dataset with an interaction term: design = ~ cell_type * treatment_duration. What extra coefficients show up in resultsNames(dds) compared to the additive ~ cell_type + treatment_duration model?
Hint

a * b is shorthand for a + b + a:b. The a:b term is the interaction.

Solution 
dds <- DESeqDataSetFromMatrix(round(cnt), cond, ~ cell_type * treatment_duration)
dds <- DESeq(dds)
resultsNames(dds)

You get the same coefficients as the additive model plus one interaction coefficient per non-reference combination of the two factors (i.e. \((k_1-1)\times(k_2-1)\) extra columns in the model matrix, where \(k_i\) are the number of levels). Each interaction coefficient measures how much the treatment effect differs between cell lines — a non-zero value means the drug works differently in the two cell types.

  • QE3.2 Using resultsNames(dds) from the interaction model, pull out (a) the main effect of treatment in the reference cell line, and (b) the interaction term itself. What is the biological interpretation of each?
Hint

With an interaction, the treatment_duration_* coefficient is no longer the average treatment effect across cell lines — it is the treatment effect in the reference cell line only.

Solution 
resultsNames(dds)
# (a) treatment effect in the reference cell line:
res_main <- results(dds, name = "treatment_duration_treated_vs_untreated")
# (b) interaction: how much bigger/smaller is the treatment effect in the other cell line
res_int  <- results(dds, name = "cell_typeX.treatment_durationtreated") # exact name from resultsNames
  1. tells you which genes respond to the drug in the reference cell line. (b) tells you which genes respond differently in the second cell line vs. the reference — significant hits here are genes where the drug’s effect is cell-type-specific. Often what you actually want to report.
  • QE3.3 What is the practical difference between testing a main effect of treatment_duration and testing the interaction cell_type:treatment_duration? When would you prefer one over the other?
Hint

Think about the null hypothesis being tested in each case.

Solution
  • Main effect of treatment: \(H_0\) is “the drug has no effect” (in the reference cell line, when the model includes an interaction; or averaged across cell lines, in a purely additive model). Use this when you want a list of generally drug-responsive genes.
  • Interaction: \(H_0\) is “the drug effect is the same in both cell lines”. Significant interaction hits are genes whose response is cell-type-specific — e.g. potential resistance markers or selectivity markers.

You’d typically run both: main effect to find the drug’s general signature, interaction to find genes that explain differential sensitivity. A likelihood-ratio test (DESeq(dds, test = "LRT", reduced = ~ cell_type + treatment_duration)) lets you test the whole interaction block at once.
