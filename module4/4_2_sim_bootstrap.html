4.2 Simulations and bootstrapping

Sometimes the math just becomes too difficult, and it is better to let the computer figure things out. In this lesson, we will look at how simulations given a mathematical model can be used to analyse its behaviour. In particular, when the model has an element of randomness, we can look at the distributions of properties over repeated simulations — which in statistics is called “bootstrapping”. The integrals required for Bayesian statistics (next module) are actually solved using a type of bootstrap (Markov chain Monte Carlo), but here we will restrict ourselves to much simpler and more general cases.

We included bootstrapping in this course simply because it is such a Swiss army knife in bioinformatics. It’s easy to implement, and thus ubiquitous!

Study advice: The rest of module 4 does not depend on this submodule. If you get stuck, or are short on time, you can come back and finish it later.

Computationally intensive methods, and bootstrap

Introduction: See this video that introduces the concept (Canvas/Kaltura: 5_5 Bootstrap; please ignore the video numbering).

Use basic bootstrap to prove the central limit theorem:

The central limit theorem states that the average of N i.i.d. variables having variance \(\sigma^2\) converges toward a normal distribution with variance \(\sigma^2 / N\). With bootstrap we can show also what a complex distribution it can have for small N!

  • Take inspiration from bootstrap_basics.R (in bootstrap_and_sim.zip).

  • As for the number of bootstraps, just keep it “somewhat high”. The higher it is, the more precise is your answer. Motivating the number of bootstraps is beyond this course. In practice, the number is picked based on experience. By running the same bootstrap multiple times, you can assess if the precision appears “good enough” for your problem. Tricks to increase precision include parametric bootstrapping, and bias correction. Again, both of these are outside this course, but see Deep reading at the end of this module.

  • Q1.1. Plot the distribution of the mean for several different N; get an intuition for what is going on.

Hint

For each N, draw N samples from your base distribution, take the mean, and repeat many times. replicate() is your friend.

Hint

Use hist() (or ggplot) on the vector of means. Try N <- c(1, 2, 5, 10, 50) and use par(mfrow=c(2,3)) to see them side by side.

Solution 
nboot <- 10000
Ns <- c(1, 2, 5, 10, 50)
par(mfrow = c(2, 3))
for (N in Ns) {
  means <- replicate(nboot, mean(runif(N)))  # base dist = Uniform(0,1)
  hist(means, breaks = 40, main = paste("N =", N), xlab = "sample mean")
}
# As N grows the histogram narrows and looks more Gaussian — the CLT in action.
  • Q1.2. Change the distribution of the samples to be Poisson(5). What does the distribution of the mean look like?
Hint

Swap runif(N) for rpois(N, lambda = 5). Everything else stays the same.

Solution 
nboot <- 10000
Ns <- c(1, 2, 5, 10, 50)
par(mfrow = c(2, 3))
for (N in Ns) {
  means <- replicate(nboot, mean(rpois(N, lambda = 5)))
  hist(means, breaks = 40, main = paste("N =", N), xlab = "sample mean")
}
# For N=1 you see the discrete Poisson; as N grows it becomes a smooth bell
# centred at 5 with variance 5/N — exactly what the CLT predicts.
  • Q1.3. Optional: Make the distribution of the samples a Gaussian mixture model and see how it affects things.
    • GMMs are also used for unsupervised clustering. If you are interested, see for example this video for an introduction to how they can be fitted to data: https://www.youtube.com/watch?v=REypj2sy_5U.
Hint

To sample from a GMM: first pick a component (e.g. with sample() according to mixture weights), then draw from that component’s rnorm().

Hint

A two-component mixture with well-separated means gives a clearly bimodal base distribution — but the mean-of-N still converges to a single Gaussian.

Solution 
rgmm <- function(n, mus = c(-3, 3), sds = c(1, 1), w = c(0.5, 0.5)) {
  k <- sample(seq_along(mus), n, replace = TRUE, prob = w)
  rnorm(n, mean = mus[k], sd = sds[k])
}

nboot <- 10000
Ns <- c(1, 2, 5, 10, 50)
par(mfrow = c(2, 3))
for (N in Ns) {
  means <- replicate(nboot, mean(rgmm(N)))
  hist(means, breaks = 40, main = paste("N =", N), xlab = "sample mean")
}
# N=1: clearly bimodal. As N grows the bimodality vanishes and a single
# Gaussian emerges around the overall mean. The CLT works even for ugly
# base distributions, as long as the variance is finite.

Use bootstrap over a simulation of a birth-death process:

  • The example code is in birth_death.R (in bootstrap_and_sim.zip).
  • Q2.1 Very optional, if you like math. If X ~ Poisson(a) and Y ~ Poisson(b), show that X+Y ~ Poisson(a+b).
Hint

This is mainly a brute-force exercise in computing sums. Use that X and Y are positive variables, and thus the sum is finite.

Hint

Write \(P(X+Y=n)\) as a convolution \(\sum_{k=0}^{n} P(X=k)\,P(Y=n-k)\). Pull out \(e^{-(a+b)}/n!\) and recognise the binomial theorem inside.

Solution

Using independence and the convolution formula, \[ P(X+Y=n) = \sum_{k=0}^{n} P(X=k)\,P(Y=n-k) = \sum_{k=0}^{n} \frac{a^{k} e^{-a}}{k!}\,\frac{b^{n-k} e^{-b}}{(n-k)!}. \] Factor out the constants and multiply by \(n!/n!\): \[ = \frac{e^{-(a+b)}}{n!} \sum_{k=0}^{n} \binom{n}{k}\, a^{k}\, b^{n-k}. \] By the binomial theorem the sum equals \((a+b)^n\), so \[ P(X+Y=n) = \frac{(a+b)^{n} e^{-(a+b)}}{n!}, \] which is exactly the pmf of \(\text{Poisson}(a+b)\). \(\blacksquare\)

  • Q2.2 If you start with n=10, and \(\alpha = 0.95\), what is the average time until the population dies out?
    • To compute the average, wrap all the code in a loop, and run it multiple times. Keep the time of death for each iteration in the loop.
Hint

You do not need to use functions if you prefer not; you can instead opt to wrap all the code inside a plain for-loop.

Hint

In a for-loop, you can keep adding values to a list as follows: mylist <- c(); for (...) { ...... mylist <- c(mylist, new_value) }

Solution 
alpha <- 0.95
n0    <- 10
nboot <- 2000

times_of_death <- c()
for (b in 1:nboot) {
  n <- n0
  t <- 0
  while (n > 0) {
    n <- rbinom(1, n, alpha)   # each individual survives with prob alpha
    t <- t + 1
  }
  times_of_death <- c(times_of_death, t)
}

mean(times_of_death)
# Roughly ~65 timesteps for n0=10, alpha=0.95 (exact value varies with seed).
  • Q2.3 If you start with n=10, and \(\alpha = 0.95\), what is the standard deviation of the time until death?
Hint

Reuse the times_of_death vector from Q2.2 and call sd().

Solution 
sd(times_of_death)
# Typically around 18-20 timesteps — the distribution is fairly broad and right-skewed.
hist(times_of_death, breaks = 40)
  • Q2.4 Optional: A measure of relative variance is std(t) / mean(t); qualitatively, how does this depend on n?
    • bonus: Generate a plot showing the trend.
Hint

Wrap Q2.2 in an outer loop over starting populations n0. Save mean and sd for each.

Hint

The ratio sd/mean decreases as n0 grows — larger starting populations have more deterministic crash times (relatively speaking).

Solution 
alpha <- 0.95
nboot <- 1000
n0s   <- c(2, 5, 10, 20, 50, 100, 200)

ratios <- sapply(n0s, function(n0) {
  ts <- replicate(nboot, {
    n <- n0; t <- 0
    while (n > 0) { n <- rbinom(1, n, alpha); t <- t + 1 }
    t
  })
  sd(ts) / mean(ts)
})

plot(n0s, ratios, type = "b", log = "x",
     xlab = "starting n", ylab = "sd(t) / mean(t)")
# Ratio shrinks with n — relative noise drops, consistent with a 1/sqrt(n)-ish trend.
  • Q2.5 Optional: The average follows a normal distribution, with the induced variance \(\sigma^2 / n\); how many bootstraps need you generate to get the variance of mean time to population crash within ±1 individual, with 95% confidence interval? (This is a bit more mathy; if you know \(\sigma\) then qnorm() and some math can give you n.)
Hint

A 95% CI for the mean has half-width \(1.96 \cdot \sigma / \sqrt{n}\). Set this equal to 1 and solve for \(n\).

Solution

We require \(1.96 \cdot \sigma / \sqrt{n} \le 1\), i.e. \(n \ge (1.96\,\sigma)^2\).

sigma <- sd(times_of_death)         # from Q2.3, e.g. ~19
n_needed <- ceiling((qnorm(0.975) * sigma)^2)
n_needed
# With sigma ~= 19 this gives n_needed ~= 1400 bootstraps.

  • Q3.2 Play with the parameters. For how long can you make it cycle? What seems to make the population crash? (no single correct answer)
Hint

Try lowering predator efficiency or increasing prey reproduction — cycles widen. Crashes tend to happen when a population dips below ~1 and rounding/randomness kills the last individual.

Solution

There is no single correct answer. Typical observations:

  • Small finite populations crash quickly because Poisson/binomial noise can wipe out predators or prey when their count is low.
  • Very aggressive predation (high attack rate) overshoots the prey and then predators starve.
  • Balanced parameters with larger starting populations can cycle for thousands of timesteps before noise eventually causes a crash.
# Example: try a parameter sweep, looking at survival time
# (see Q3.3 for the wrapped function).
  • Q3.3 Wrap the simulation in a function so you can bootstrap it.
Hint

Make the parameters (n_prey0, n_pred0, the rates, tmax) function arguments. Return a data frame or list with the trajectories and the time-of-crash.

Solution 
simulate_lv <- function(n_prey0 = 100, n_pred0 = 20,
                        a = 0.1, b = 0.005,
                        c = 0.005, d = 0.05,
                        tmax = 2000) {
  prey      <- numeric(tmax); prey[1]      <- n_prey0
  predators <- numeric(tmax); predators[1] <- n_pred0
  t_crash   <- NA
  for (t in 2:tmax) {
    # ... whatever update rule lotka_volterra.R uses,
    # written in terms of the function arguments above.
    if (prey[t] <= 0 || predators[t] <= 0) { t_crash <- t; break }
  }
  list(prey = prey, predators = predators, t_crash = t_crash)
}

Hint

Call simulate_lv() many times with replicate(), pull out t_crash, and take mean(). Treat runs that survive to tmax carefully — either bump up tmax or exclude them.

Solution 
nboot <- 500
ts <- replicate(nboot, simulate_lv()$t_crash)
mean(ts, na.rm = TRUE)
# The exact value depends entirely on the parameters chosen.
  • Q3.5 What is the variance in time? Is the distribution symmetric?
Hint

var(ts) and sd(ts); check symmetry visually with hist(ts) and compare mean(ts) to median(ts).

Solution 
var(ts, na.rm = TRUE)
sd(ts,  na.rm = TRUE)
hist(ts, breaks = 40)
abline(v = mean(ts, na.rm = TRUE), col = "red")
abline(v = median(ts, na.rm = TRUE), col = "blue")
# Typically right-skewed: many runs crash relatively early, with a long tail
# of "lucky" runs that cycle for a long time. mean > median.
  • Q3.6 Assuming the model can run for eternity (simply ignore any samples after it crashes), what is the average number of prey?
Hint

For each run, take prey[1:t_crash-1] (the pre-crash trajectory) and average those. Then average across runs.

Hint

Equivalently: pool all pre-crash prey counts from all bootstrap runs into one big vector and take the mean.

Solution 
nboot <- 500
all_prey <- c()
for (b in 1:nboot) {
  sim <- simulate_lv()
  tc  <- if (is.na(sim$t_crash)) length(sim$prey) else sim$t_crash - 1
  all_prey <- c(all_prey, sim$prey[1:tc])
}
mean(all_prey)
# This is the long-run time-average prey population, conditional on survival.

Bootstrap of the mean (extra)

  • QE1.1 Repeat the CLT demo with an exponential base distribution, rexp(N, rate = 1). The exponential is strongly right-skewed — at what N does the distribution of the mean start to look Gaussian?
Hint

Same template as Q1.1: replicate(nboot, mean(rexp(N, rate = 1))). Loop over a few values of N and hist() each.

Hint

The theoretical mean is 1/rate = 1 and variance is 1/rate^2 = 1, so the distribution of the mean should be centred on 1 with variance 1/N. Skew is still visible at N=5 but mostly gone by N=30 or so.

Solution 
nboot <- 10000
Ns <- c(1, 2, 5, 10, 30, 100)
par(mfrow = c(2, 3))
for (N in Ns) {
  means <- replicate(nboot, mean(rexp(N, rate = 1)))
  hist(means, breaks = 40, main = paste("N =", N), xlab = "sample mean")
}
# Heavy right-skew at small N gradually symmetrises; by N~30 it is visually
# indistinguishable from a Gaussian centred at 1 with sd ~ 1/sqrt(N).
  • QE1.2 Try a log-normal base distribution, rlnorm(N, meanlog = 0, sdlog = 1). How does the convergence speed compare to the exponential?
Hint

Log-normal is even more skewed than exponential — its tail is heavier. Expect to need larger N before the mean looks Gaussian.

Solution 
nboot <- 10000
Ns <- c(1, 5, 30, 100, 300, 1000)
par(mfrow = c(2, 3))
for (N in Ns) {
  means <- replicate(nboot, mean(rlnorm(N, meanlog = 0, sdlog = 1)))
  hist(means, breaks = 40, main = paste("N =", N), xlab = "sample mean")
}
# Convergence is slower than for the exponential: even at N=100 there is
# visible right-skew. The CLT still works, but heavy tails slow it down.
  • QE1.3 Now try the Cauchy distribution, rcauchy(N). The CLT fails here — generate the distribution of the mean for increasing N and explain in prose what goes wrong.
Hint

The Cauchy has undefined mean and infinite variance — the assumptions of the CLT are violated.

Hint

In fact, the mean of N Cauchy samples is itself Cauchy-distributed (with the same scale). So averaging does not help at all.

Solution 
nboot <- 10000
Ns <- c(1, 10, 100, 1000)
par(mfrow = c(2, 2))
for (N in Ns) {
  means <- replicate(nboot, mean(rcauchy(N)))
  hist(means, breaks = 100, main = paste("N =", N),
       xlab = "sample mean", xlim = c(-20, 20))
}

Prose: The CLT requires the base distribution to have finite variance. The Cauchy has no defined mean and infinite variance, so the theorem does not apply. Empirically: the distribution of mean(rcauchy(N)) does not narrow as N grows — it stays Cauchy-distributed with the same scale parameter. The “law of large numbers” also fails: the sample mean does not converge to any fixed value. This is the canonical cautionary example for heavy-tailed data in biology (e.g. some gene-expression and network-degree distributions).

# Quick sanity check: sample variance of the mean does not shrink with N.
set.seed(1)
var(replicate(2000, mean(rcauchy(10))))
[1] 3543.705
var(replicate(2000, mean(rcauchy(1000))))
[1] 7279.409
# Both are large and erratic — no 1/N scaling.

Birth-death (extra)

  • QE2.1 Run the birth-death simulation with n0 = 10 and alpha = 0.99 (a much more “stable” population). Estimate the probability that the population survives past T = 500 timesteps.
Hint

For each bootstrap iteration, run the simulation up to T timesteps and record whether n > 0 at the end. The empirical survival probability is just the mean of that 0/1 vector.

Solution 
alpha <- 0.99
n0    <- 10
T     <- 500
nboot <- 2000

survived <- replicate(nboot, {
  n <- n0
  for (t in 1:T) {
    n <- rbinom(1, n, alpha)
    if (n == 0) break
  }
  n > 0
})

mean(survived)   # empirical P(survive past T)
# With alpha=0.99 and n0=10 a sizeable fraction makes it past 500 steps,
# but many runs still die out — the exact figure depends on the seed.
  • QE2.2 Vary the initial population n0 over a range (e.g. c(2, 5, 10, 20, 50, 100)) at fixed alpha = 0.95. Plot mean time-of-death against n0. Is the relationship linear, logarithmic, or something else?
Hint

Wrap the inner simulation in replicate(), sweep n0, and plot(n0s, mean_t). Try both linear and log axes.

Hint

Mean time-to-extinction grows roughly logarithmically in n0 for a Galton-Watson-like process at fixed per-individual survival.

  • QE2.3 Optional: For alpha = 0.95, estimate the median and interquartile range of the time-of-death starting from n0 = 10. Compare to the mean and sd from Q2.2/Q2.3. Why might the median be a more honest summary?
Hint

median() and quantile(x, c(0.25, 0.75)). The distribution is right-skewed, so the mean is pulled up by the long tail.

Solution 
alpha <- 0.95
n0    <- 10
nboot <- 2000
ts <- replicate(nboot, {
  n <- n0; t <- 0
  while (n > 0) { n <- rbinom(1, n, alpha); t <- t + 1 }

  • QE3.1 Sensitivity analysis. Using simulate_lv() from Q3.3, vary the predator death rate gamma over c(0.02, 0.05, 0.08, 0.12, 0.2) while keeping all other parameters fixed. For each value, estimate mean time-to-crash from nboot = 200 runs. Which gamma lets the system survive longest?

gammas <- c(0.02, 0.05, 0.08, 0.12, 0.2)

Hint

Larger starting populations and gentler rates are more forgiving of stochastic noise. Try n_prey0 = 500, n_pred0 = 100, mild a, b, c, d.

Solution 
nboot <- 200
res <- replicate(nboot, simulate_lv(

  • QE3.3 Estimate the average period of the prey-predator oscillation in phase space for one long surviving run. (Use any reasonable definition, e.g. consecutive maxima of the prey trajectory.)
Hint

A simple way: find local maxima of prey with which(diff(sign(diff(prey))) == -2) + 1, then take diff() of those indices and average.

Solution 
sim <- simulate_lv(n_prey0 = 500, n_pred0 = 100,
                   a = 0.1, b = 0.001, c = 0.001, d = 0.05,
                   tmax = 5000)
prey <- sim$prey
# Smooth a little so noise does not create spurious local maxima
prey_s <- stats::filter(prey, rep(1/21, 21), sides = 2)
peaks  <- which(diff(sign(diff(prey_s))) == -2) + 1
periods <- diff(peaks)
mean(periods); sd(periods)
# Period depends on parameters; the classical continuous LV has period
# ~ 2*pi/sqrt(a*c) in the linearised regime around equilibrium.

Bonus: SIR and HWE

  • QE4.1 Run sir_basic.R from the zip. Compute the peak infected fraction (max(I) / popsize) and the day at which the peak occurs. Bootstrap it: wrap the simulation in a function and run it nboot = 200 times — what is the distribution of the peak fraction?
Hint

Copy the body of sir_basic.R into a function simulate_sir(beta = 0.1, gamma = 0.1, popsize = 20, ndays = 50) returning the per-day SIR counts. Compute max(I)/popsize from each run.

Solution 
simulate_sir <- function(beta = 0.1, gamma = 0.1,
                        popsize = 20, ndays = 50) {
  indiv <- data.frame(num = 1:popsize, state = "S")
  indiv$state[1] <- "I"
  log_SIR <- matrix(0, nrow = ndays, ncol = 3,
                    dimnames = list(NULL, c("S","I","R")))
  for (d in 1:ndays) {
    log_SIR[d, ] <- c(sum(indiv$state == "S"),
                      sum(indiv$state == "I"),
                      sum(indiv$state == "R"))
    next_indiv <- indiv
    rate <- sum(indiv$state == "I") * beta
    next_indiv$state[indiv$state == "S" &
                     runif(nrow(indiv)) < rate] <- "I"
    next_indiv$state[indiv$state == "I" &
                     runif(nrow(indiv)) < gamma] <- "R"
    indiv <- next_indiv
  }
  log_SIR
}

nboot <- 200
peaks <- replicate(nboot, {
  m <- simulate_sir()
  max(m[, "I"]) / 20
})
hist(peaks, breaks = 30, xlab = "peak infected fraction")
mean(peaks); sd(peaks)
# Highly variable for popsize = 20 — many epidemics fizzle out, a few explode.
  • QE4.2 Optional: Complete the hwe.R script (fill in the #TODO lines so each child draws one allele uniformly at random from each parent). Run it for 50 generations starting from half AA and half aa, and check that genotype frequencies stabilise near the Hardy–Weinberg expectation \(p^2 : 2pq : q^2\) with \(p = q = 0.5\) (i.e. 25% AA, 50% Aa, 25% aa).
Hint

sample(c(parent$allele1, parent$allele2), 1) picks one of the two parental alleles uniformly.

Hint

After completing the loop, plot log_num$num_AA / popsize, num_Aa / popsize, num_aa / popsize over generations and compare to 0.25, 0.50, 0.25.

Solution 
popsize <- 200   # bump up so HWE is visible above drift noise
indiv <- data.frame(num = 1:popsize, allele1 = "A", allele2 = "A",
                    stringsAsFactors = FALSE)
indiv$allele1[(popsize/2 + 1):popsize] <- "a"
indiv$allele2[(popsize/2 + 1):popsize] <- "a"

log_num <- NULL
for (gen in 1:50) {
  log_num <- rbind(log_num, data.frame(
    num_AA = sum(indiv$allele1 == "A" & indiv$allele2 == "A"),
    num_aa = sum(indiv$allele1 == "a" & indiv$allele2 == "a"),
    num_Aa = sum(indiv$allele1 != indiv$allele2)
  ))
  p1 <- sample(1:popsize, popsize, replace = TRUE)
  p2 <- sample(1:popsize, popsize, replace = TRUE)
  next_indiv <- data.frame(allele1 = NA, allele2 = NA)
  for (i in 1:popsize) {
    a1 <- sample(c(indiv$allele1[p1[i]], indiv$allele2[p1[i]]), 1)
    a2 <- sample(c(indiv$allele1[p2[i]], indiv$allele2[p2[i]]), 1)
    next_indiv[i, ] <- c(a1, a2)
  }
  indiv <- next_indiv
}

tail(log_num / popsize)
# After a few generations: ~0.25 AA, ~0.50 Aa, ~0.25 aa,
# matching Hardy-Weinberg with p = q = 0.5 (modulo drift).
